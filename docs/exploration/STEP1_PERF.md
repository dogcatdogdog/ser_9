## 0. 结论摘要

| 项 | 结果 |
|---|---|
| 正确性 | **逐位 (bitwise) 不变** —— 与参照实现 / 暴力枚举的最优能耗与序列完全相同 |
| 主导加速 | **分层 + numpy 向量化：稳定 ~25×**（与 n 无关的常数因子） |
| 剪枝附加 | **1.0× ~ 2.2×**，随 n 增大；状态削减 42%~94%；峰值内存最多降 21%（n=20） |
| 综合加速 | **19.6× (n=15) → 49~54× (n=20)** |
| 覆盖阈值 | **n ≤ 20（MVP 上限）全部落在服务端 5 s / 250 MB 预算内**（最差 1.96 s / 156 MB） |

> ⚠️ **一条重要的口径更正**：任务背景里的"n=15 要 19.7 s、n=18 要 223 s"
> 是 **`tracemalloc` 在计时**时测出来的数（`run_adaptive_validation.py` 的写法）。
> `tracemalloc` 追踪每一次浮点分配，对纯 Python 参照实现的惩罚（本机实测 **11×**）
> 远大于 numpy 实现（3×），因此那样测出来的"加速比"会被高估数倍。
> 去掉 tracemalloc 后，n=15 的参照实现只要 **1.62 s**（n=18 为 18.5 s，n=20 为 96.5 s）。
> **STEP2 定阈值时必须改用纯净计时**，否则会得出"只能精确到 n=15"的错误结论。

## 1. 改造前的瓶颈

原实现一次性分配 `dp[2^n][n+1]` 并遍历全部 `2^n` 个 mask；
对每个可达状态再对全部未访问点做一次 Python 级转移 —— 即 `O(2^n·n²)` 次
**解释器循环**（n=18 时约 8500 万次），内存 `2^n·n·8B` 恒定占用。
瓶颈是解释器开销与状态空间的全量遍历，不是算法本身。

## 2. 三项改造

### 2.1 分层推进（按 popcount）

第 k 层只保留"恰好访问 k 个点"的状态。层内 mask 用 `np.bitwise_count` 一次性划分，
天然按数值升序（= colex 序）排列；配一个 `row_of_mask: mask -> 层内行号`
全局索引数组，做到 O(1) 定位。

| | 改造前 | 改造后 |
|---|---|---|
| 内存布局 | 单个 `2^n × (n+1)` 数组 | 每层 `C(n,k) × (n+1)`，仅两层同时存活 |
| 层内状态 | 全部 `2^n` 个 mask 都分配行 | 只分配该层 mask；**剪枝后再按行压实** |

**"压实"是关键**：每层建完后，若某 mask 的所有列都被剪掉/不可达，整行直接丢弃，
`dp_cur` / 父指针 / mask 数组三者同步收缩。内存因此只在
`O(max_k C(n,k)·k)` 量级，且**随剪枝强度进一步下降**（实测 n=20：156 MB → 120 MB）。

回溯所需的父指针按层保存（只存"上一个点"，上一个 mask 由 `mask ^ bit_j` 反推），
用 `int8` 存（n ≤ 127 足够）。

### 2.2 numpy 向量化转移

同一层内，"某 mask 的状态 j 转移到未访问点 k" 被重组为**按目标点 k 分组的批量运算**：
对固定 k，取出该层中所有不含 k 的 mask，一次算出 `(m, n+1)` 的代价矩阵

```
cols[r, j] = dp_prev[r, j] + d(j, k) · (α + β·rem_load[r])
```

再 `argmin(axis=1)` 取每个 mask 的最优前驱 j。numpy 的 argmin 取**首个**最小值，
与参照实现"j 升序、严格小于才更新"的并列规则一致 —— 因此**序列也逐位相同**，
不只是目标值相同。整个过程只有 `n` 次 numpy 调用/层。

距离矩阵刻意用 `energy_model.euclidean_distance`（`math.sqrt`）逐元素填充，
不用 numpy 广播，以保证与参照实现逐位相同的浮点结果。

### 2.3 上界剪枝

1. **上界 UB**：先用现有启发式 `a3_python.solver.plan_multistop` 求可行解并取其能耗。
   注意**必须用序列重算精确能耗**，不能直接采信 `RoutePlan.total_energy_consumed`
   （它保留 2 位小数，可能比真值小 0.005，而 UB 一旦低于真实最优就会被误剪）。
   启发式不可行时退回多起点贪心 NN；仍不可行则 `UB = +∞`（等价于不剪枝）。
2. **下界 LB（可采纳）**：对状态 `(mask, j)`，记 `S` = 未访问点集合：

   ```
   LB(mask) = Σ_{i∈S} (α + β·q_i)·minin(i)  +  α · min_{i∈S} d(i, home)
   ```

   其中 `minin(i) = min_{i'≠i} d(i', i)`（对全部点取最小，含已访问点与 home）。
   第一项用子集和数组预计算（`_subset_sums`，向量化 DP，O(n·2^n)）。

   **可采纳性（即 LB ≤ 真实剩余能耗）证明**：
   设剩余航段 `j → v₁ → … → v_m → home`（`S = {v₁..v_m}`，共 m+1 段）。
   - α 部分：m 个"抵达某 i∈S"的航段与 S 一一对应，第 i 段长度 ≥ `minin(i)`；
     返航段起点 `v_m ∈ S`，长度 ≥ `min_{i∈S} d(i,home)`。
     故 `α·Σd_ℓ ≥ α·[Σ_{i∈S} minin(i) + min_{i∈S} d(i,home)]`。
   - β 部分：真实为 `β·Σ_ℓ d_ℓ·L_ℓ`（`L_ℓ` = 该段出发时载重）。记 `ℓ_i` 为
     抵达 i 的航段，出发时 i 尚未投递 ⇒ `L_{ℓ_i} ≥ q_i`；各 `ℓ_i` 互不相同，
     返航段载重为 0（对 β 部分贡献 0）。故 `β 部分 ≥ β·Σ_{i∈S} q_i·minin(i)`。

   两项相加即得。**这比"一律用 α 乘距离"的朴素版本更强**：它把 `β·q_i·minin(i)`
   也计入下界，用的正是"载重非负 ⇒ 能耗率 `α+βL ≥ α`"这一事实。

3. **剪枝判据**：`cost + LB > UB + ε` 的状态整行丢弃 —— 任何延伸的完成代价
   `≥ cost + LB > UB`，不可能严格优于已知可行解，故最优解不丢。
   用严格 `>` 是为守住"最优解恰好等于 UB"的边界（见 §3.2）。满 mask 层不剪枝。

## 3. 正确性验证

### 3.1 逐位一致（不是 approx）

改造后实现 vs **参照实现**（原三重循环，逻辑一字未改，仅重命名）
vs **暴力枚举**全排列，在 n=5,6,7,8 × {random, circle, cluster} × 多种子
（含"电量上限恰等于最优值"的极端点）上断言：

- 可行性一致；**最优能耗 `==` 逐位相同**；**访问序列一致**。

浮点逐位一致并非自动成立 —— 首轮改造实测有 4/90 个实例出现 **1 ULP**
（1.137e-13）偏差，根因是两处求和顺序：① `total_demand` 由 numpy 分段求和
改为 Python 顺序求和；② 已投递需求量由"按位从低到高"改为**按位从高到低**累加，
以对齐参照实现的 `mask_demand[mask] = mask_demand[mask ^ low] + demand[low]` 递推。
两处修好后偏差归零。

> **浮点口径提示（供 STEP3 移植参考）**：本模块定义的口径是
> `出发载重 = total_demand − mask_demand[mask]`（子集和递推）；
> 而 `energy_model.simulate_route_energy` 用的是"载重逐点累减"。
> 两者数学等价，浮点上可能差 ~1 ULP。若 Rust 侧按逐点累减实现，
> 与 Python 精确 DP 的**逐位**交叉验证会失败（差 1 ULP），需按本口径对齐
> 或在断言里留 1e-9 容差。

### 3.2 剪枝边界用例（专门守"最优解贴近上界"）

- 以参照实现先算出真实最优 `OPT`，再用 `ub_override=OPT`（**最紧的合法上界**）调加速版：
  此时最优路径上每个状态恰好落在 `cost + LB ≤ UB` 的边界，若判据写成 `≥` 就会剪掉最优解。
  断言：能耗与序列仍与参照逐位相同。
- 最紧组合用例：**电量上限 = OPT 且剪枝上界 = OPT**（§3.5 的闸门性质允许这样做），
  每个中间状态的累计能耗都顶到电量上限、剪枝判据同时取等号，仍不误剪，
  且断言 `pruned_states > 0`（确保该用例确实触发了剪枝而非空跑）。
- n=10 版本同做。

### 3.3 下界可采纳性的直接验证

不依赖端到端结果：对 n=5,6 的**每一个** `(mask, j)`，用暴力枚举
（枚举 S 的全部排列，从 j 出发回到 home）算出**真实剩余最优能耗**，
断言 `LB(mask) ≤ 真实剩余最优 + 1e-12`。
这是剪枝正确性的根：只要 LB 可采纳，剪枝就不可能丢最优解。

### 3.4 其他

- 开关等价：`use_pruning=True/False`、`vectorized=True/False` 三路结果逐位一致；
- 大 n 自洽：n=13/15 上用独立复算脚本按返回序列重算能耗，与 `objective` 相等；
- 退化：空目标集、单点、超载重、电量过小、超点数上限；
- 回归：`tight_10p_s9`（启发式失败案例）与中度电量多种子扫描。

### 3.5 顺带发现：**电量约束在本问题里只是"可行性闸门"**

写"电量绑定"用例时发现：**不存在"电量绑定但仍可行且最优解变差"的实例**。这不是测试写错，
而是一条三行可证的结构性事实：

> 目标 = 全程总能耗；累计能耗单调不减，故约束"任意时刻 ≤ cap" ⟺ "总能耗 ≤ cap"。
> 设无约束最优为 `OPT`：`cap ≥ OPT` ⟹ 最优解本身可行 ⟹ 约束解 = 无约束解；
> `cap < OPT` ⟹ 任何解的总能耗 ≥ OPT > cap ⟹ **无可行解**。

实测 36 个实例 × 5 档 cap，**0 例违背**（`cap = OPT ± 1e-6` 两侧行为完全如命题所述）。
两个直接后果（已在单测中钉死）：

1. `solve_energy_exact_battery` 的最优**序列**与 MVP 已有的无约束精确 DP
   `exact.solve_energy_exact_dp` **完全相同**（实测 30/30 实例序列一致）。
   两者唯一的差别是本模块还能判定 `cap < OPT` 时**不可行**。
2. `WMLP_INSIGHT.md` §2 的表述"此前从未算出过该问题的真实最优"需要修正：
   由于约束不改变最优解，"带电池能量最优"与 `solve_energy_exact_dp` 已是同一个最优；
   真正新增的信息只有**可行性判定**与**WMLP 恒等式**本身。
   （§3 的 gap 重算表用哪一支去算都一样，数值不变。）

> 本文件只陈述事实，**未修改** `WMLP_INSIGHT.md` / `TW_FEASIBILITY.md`（结论回写待评审）。

1. **主导因素是分层 + 向量化**：加速比一列稳定在 **24~26×**，是与 n 无关的常数因子。

3. n ≤ 20（MVP 上限）**全部落在服务端 5 s 预算内**（最差 1.96 s），内存亦满足。

## 5. 剪枝的实际收益与限度

### 5.1 下界有多紧？

实测 layer-0 下界（即"全程剩余能耗下界"）：

| n | OPT (Wh) | LB(layer 0) | LB/OPT |
|---|---|---|---|
| 15 | 1167.57 | 522.86 | **44.8%** |
| 16 | 1210.76 | 537.92 | **44.4%** |
| 17 | 1278.48 | 513.63 | **40.2%** |

即"入边指派松弛"只覆盖真实代价的 4 成多 —— 这是该类松弛在欧氏实例上的典型水平
（每条入边用"全局最近点"近似，忽略了"源点必须尚未访问"与"路径无子回路"两条结构约束）。
这条上限决定了剪枝不可能把状态空间削掉几个数量级。

更值得注意的是：**UB 不是瓶颈**。把 UB 强行设为真实最优（`ub_override=OPT`）时，
剪枝率与用启发式 UB 时几乎一样，说明瓶颈完全在 LB 一侧。
因此"换更好的启发式"对剪枝没有帮助，只有更强的下界才有用 —— 而更强的下界
（Held-Karp / 1-tree / 拉格朗日松弛）需要逐状态求解线性松弛，单状态 O(n³)，得不偿失。

### 5.2 值不值得

| 维度 | 结论 |
|---|---|
| 正确性 | 无损。逐位一致 + 下界可采纳性直接验证 + 边界用例 |
| 速度 | n≤16 与"仅向量化"持平；n≥17 净收益，n=20 达 2.0× |
| 内存 | n≥17 起下降，n=20 降 21%（层内行压实） |
| 定位 | **锦上添花，不是主力**：主力是分层 + 向量化（稳定 ~25×） |

### 5.3 这套精度能覆盖到多大 n？

- **n ≤ 20 全范围**：最差 1.96 s / 156 MB，典型 0.82 s / 120 MB —— 全在服务端
  5 s / 250 MB 预算内。即 **MVP 声明的目标点数上限（`MAX_TARGETS = 20`）现在可以精确求解**。
- **n ≥ 21 受内存限制**：峰值内存按 ~2×/n 增长（父指针 + 每层状态矩阵），
  外推 n=21 约 280 MB，将越过 250 MB 预算；时间仍在秒级。
- 改造前（纯净计时）的阈值是 **n ≤ 16**（n=17 已需 8.2 s）。
- 注：`MAX_EXACT_BATTERY_POINTS` 仍保持 15（不改既有语义），调用方用 `max_points=`
  显式放开；是否上调留待 STEP2/STEP3 决定。
