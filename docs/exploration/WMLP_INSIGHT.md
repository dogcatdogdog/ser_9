# 发现记录：总能耗的加权到达距离形式，与带电池精确解

> 日期：2026-09-10　分支 `worktree-tw-feasibility`（探索，未并入主干）

## 1. 恒等式：总能耗 = α·总距离 + β·ΣqᵢDᵢ

本问题的总能耗可**精确**改写为：

$$E=\alpha\cdot D_{\text{total}}\;+\;\beta\cdot\sum_i q_i D_i$$

其中 $D_{\text{total}}$ 为全程飞行距离，$D_i$ 为**到达投递点 $i$ 时的累计飞行距离**，
$q_i$ 为该点需求量。

**推导**（三行）：段 $i\to j$ 的能耗为 $d_{ij}(\alpha+\beta L_{ij})$，
其中 $L_{ij}$ 为该段出发时"尚未投递的需求之和"。
对 $\beta\sum_{\text{leg}}d_{\text{leg}}L_{\text{leg}}$ 交换求和次序：
每条航段 $d_{\text{leg}}$ 被计入的系数恰是"在其之后投递的全部需求量之和"，
即等于 $\sum_i q_i D_i$。

**数值验证**（`docs/patent/scripts/fig4_data.json`，残差仅来自 JSON 的 1 位小数存储）：

| 方案 | $D_{\text{total}}$ | $\sum q_iD_i$ | 恒等式预测 $E$ | 实测 $E$ | 残差 |
|---|---|---|---|---|---|
| 几何最优 | 3962.2 | 95294.9 | 872.695 | 872.710 | −0.015 |
| 本方法 | 3962.2 | **86173.8** | 827.089 | 827.080 | +0.009 |

**意义**：该问题**精确等价于**"加权最小延迟问题（WMLP / 旅行修理工问题）＋ 总距离项"。
即：$q_i$ 为权重、$D_i$ 为"完成时刻"（以距离度量）。
"先送重的还是先送近的"这一真实张力，正是 $\sum q_iD_i$ 与 $D_{\text{total}}$ 的权衡。

> ⚠️ **新颖性未定**：WMLP 及其变体自 1980 年代起被广泛研究，
> 该等价关系是否已被公开提出，须经文献核查（进行中）。
> 本记录只陈述数学事实与数值验证，不主张首创性。

## 2. 带电量约束的能量最优精确解

> **⚠️ 2026-09-10 修正（见 `STEP2_THRESHOLD.md` §3.2）**：
> 本节原称"此前从未算出过该问题的真实最优"，**该结论已被推翻**。
> 经证明与实测：电量约束（累计能耗 ≤ 电池容量）**不改变最优序列**，
> 只是一个可行性闸门（累计能耗单调不减 ⇒ "每点 ≤ cap" ⟺ "总能耗 ≤ cap"）。
> 6 实例 × 3 档电池的 18 组对照中，带电池解与无约束解的**序列 18/18 完全相同**。
> 故 `exact.py::solve_energy_exact_dp`（无电池版）给出的序列即真实最优序列。
> 带电池版的真实增量仅为：**可行性判定** + **性能**（可在线求解规模 n≤15 → n≤20）。

**实现**：`a3_python/tw/exact_battery.py::solve_energy_exact_battery`

**状态压缩依据（支配性）**：
到达同一状态 $(\text{mask}, j)$ 时，**耗能最少**的子路径剩余电量最多；
而未来可行性与代价只取决于 $(\text{mask}, j)$。
故只需为每个状态保留"最小耗能"这一条标签，**无需把电量作为独立状态维**，
状态数仍为 $O(2^n\cdot n)$，而非 $O(2^n\cdot n\cdot |\text{battery}|)$。

**验证**：
- 与暴力枚举在 n=5,6,7,8 × 多组实例上**逐位精确一致**（含电量绑定、存在剪枝的情形）；
- 在启发式**失败**的实例 `tight_10p_s9` 上，**20 ms 找到可行解**（3449.713 Wh = 34497.1 m 等效）；
- 单测 19 例（`tests/test_tw_exact_battery.py`）。

## 3. 基准重算：我们离真实最优有多远

用上述精确解对 **70 个实例**（自建 circle/random × 5/10/15 点 × 10 种子 + 电量紧张 10 点）重算。
脚本 `a3_python/tw/run_gap_rebaseline.py`，输出 `results/gap_rebaseline.{json,md}`。

| 指标 | 结果 |
|---|---|
| 实例总数 / 两者均可行 | 70 / **69** |
| **序列与精确最优完全相同** | **45 / 69 = 65.2%** |
| **gap_true**（我们 vs 真实最优） | **均值 0.429%，最大 8.643%** |
| gap ≤ 1% / ≤ 2% | **82.6% / 97.1%** |
| gap_vs_geo（MVP 旧口径） | 均值 −2.936%，最好 −13.186% |
| **真实最优相对几何基线的改善** | **均值 3.576%，最大 16.86%** |
| 本方法不可行 / 精确解不可行 | **1 / 0** |
| 精确解总耗时（70 实例） | 33.11 s |

**关键读法**：
1. 我方法在 **2/3 的实例上直接命中精确最优**，98% 的实例距最优 ≤2%。
   这是**真正有分量的质量主张**——基线是真实最优，不是"几何最优路线"。
2. MVP 旧口径（gap_eng 以几何最优序列为基线）**低估了我们的实际效果**：
   真实最优相对几何基线平均可再改善 **3.576%**，而我们做到了接近该上限。
3. **精确解在全部 70 个实例上均可现行**，而启发式在 1 个实例上失败
   —— 该失败案例现在有了 20 ms 的精确解法兜底。
